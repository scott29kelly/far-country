## Findings, ranked

### F1 — probe-wildwater.ts cannot fail (families V + VI; battery member)
`apps/world-engine/tools/probe-wildwater.ts` is the ONLY gate over the
shipped canyonlands hydrology, it is billed as a "safety check" (l.2-8:
"so a flooded plateau or a spilled lake is caught before Scott reviews the
stills"), and it has **no PASS/FAIL logic and no non-zero exit path other
than an exception** (l.127-147: prints wet counts and pockets, exits 0).
The 2026-08-18 "13/13" record describes it as "wildwater matching the
designed end state exactly" — that match was performed by the human reading
the printout. Worse, the no-case-to-answer path is fully realized: if the
`__laasDbg.engine.heightfield` handle is absent (renamed, dbg stripped,
scene changed), both page.evaluate blocks return `[]` (l.56, 103), the tool
prints a header plus empty tables, and exits 0. A flooded plateau, a drained
designed lake, AND a broken probe all produce "ran fine".
Fix shape: encode the designed end state (flat core/approach/spawn wet==0;
band pockets == west lake ~9.4 m + three ≤9 m dolines, nothing deeper) as
checks via makeChecker, and make hf-missing a distinct UNMEASURED failure.

### F2 — the battery has no executable definition (`npm run battery` is dead)
`apps/world-engine/package.json` l.14: `"battery": "tsx tools/battery.ts"`;
the file does not exist on this branch and never existed in git history.
Every "full battery ALL PASS" claim in STATUS.md has an undefined
denominator — membership lives in prose and session memory (the 2026-08-18
"12 functional + wildwater" list is reconstructible but not writable as a
command). A probe silently dropped from a session's ad-hoc run list is
family V at suite level: the suite stays green with the case removed.
Fix shape: write tools/battery.ts (or a .sh) that enumerates members
explicitly, runs them, and refuses to report green if any member is missing
or reports UNMEASURED. GA-1 step 3's third verdict lands here.

### F3 — shoot.ts writes PNGs nothing ever looks at (family I, the F1 flagship)
`apps/world-engine/tools/shoot.ts` l.173: `await page.screenshot({ path: out })`
— straight to disk, never decoded. It checks `__laas.error` (l.107) and
readiness, but the delivered artifact (the pixels) is untouched: an
all-black, all-white, or NaN-fog frame passes with exit 0 and a cheerful
`[shoot] wrote ...`. Same for cityshots.ts (l.140) — the sheet every future
critic pass stands on. This machine's GPU history (Code 43,
createBuffer-boot failures) makes the black-frame case live, not
theoretical.
Where the gate goes: in `main()` immediately after l.173 (before the stats
print), capture the buffer (`const buf = await page.screenshot(...)`
returns it), decode via sharp (already a devDependency — used by
compare/diff/horizon), and assert: mean luminance within bounds, nonzero
variance, no single value covering >99% of pixels. `scanBand` in
probe-horizon.ts l.29-56 is a working in-repo template. Failure exits 1 and
renames the file `-SUSPECT.png`. Same helper drops into cityshots.ts's
per-framing loop (l.140) and probe-bootui.
Provenance note for the bounds: derive from a set of known-good stills
(shots/wip/wildring/*) and RECORD the derivation — not from the first frame
the gate happens to see.

### F4 — no UNMEASURED verdict exists anywhere (practice 7 absent, by design of check.ts)
`tools/check.ts` `finish()` (l.23-30): empty failures array ⇒
"[probe] ALL PASS", exit 0. Nothing distinguishes "measured N things, all
good" from "measured nothing". Concrete vacuous-pass instances found:
- probe-visualkey.ts: with empty markers+vols, A1 (0===0), A2
  (missing/extra both []), A3/A4 (`every` on []), B1 (worst.d 0≤120), C1
  (zero loop iterations) all PASS; only B2/B3 fail. A registry wipe reads
  as 2 failures instead of a structural collapse — and a subtler bug that
  empties only `markers` while B2's find still matches nothing makes B2 the
  lone tripwire.
- probe-crowd.ts E5 l.384: `if (!f) continue` — if vendored names all
  mismatched archetype names, the loop checks nothing and E5 passes
  (E2 is the only guard).
- probe-entitypick.ts section C (l.210): iterates slugs from vols — zero
  vols ⇒ zero C checks emitted (A1 would fail first in practice).
- find-water.ts: hf missing ⇒ empty candidate list, exit 0.
Fix shape: give makeChecker a `measured(n, floor)` or make finish() take
the expected check count; add an explicit UNMEASURED exit code (e.g. 2)
that the future battery runner refuses to count as pass.

### F5 — probe-bootui computes its verdict and throws it away (family VI)
`tools/probe-bootui.ts` l.70-73: evaluates whether the boot overlay is
actually gone after ready, then `console.log`s it. A regression where the
overlay never dismisses prints `overlay removed after ready: false` and
exits 0. One-line fix: throw/exit 1 on !gone.

### F6 — mirror constants that can drift (family III-adjacent, class c literals)
Not self-referential calibration, but hand-mirrors of engine constants that
a retune changes on one side only:
- probe-wallcollide.ts l.74-77: 103.4 / 100 / 88 / 60.5 face constants
  (cityModel geometry re-derived by hand).
- probe-entitypick.ts l.116/120: NJ_SCALE hardcoded as `20` (the import
  exists 60 lines up).
- GROUND_Y=470 / PLAZA_TOP=GROUND+2.8 fixture mirrors in walkfling,
  wallcollide, cityfloors, population, entitypick, visualkey (comment
  "values match the NJ scene" is prose, not a mechanism).
- probe-framings.ts l.50: PLAZA_Y = 483.85 — provenance is explicitly a
  live-scene measurement (STATUS), the one true source=artifact instance
  found. Fixture-grade (feeds a stand-in terrain), so family III severity
  is low, but it should be derived or provenance-tagged.
- probe-gamepad.ts / probe-navigation.ts: rate/speed tables (1.2, 0.9,
  24/60/150, 4.6, 0.08, walkScale 2/4/8) mirror FlyCamera/GamepadInput
  constants as literals — a deliberate contract pin, but unlabeled; a
  retune must change both sides, and nothing detects a one-sided change of
  the PROBE.
- probe-visualkey-live.ts l.19: TIER_HEX mirrors EntityHud palette.
Fix shape per §4a-III: every such number gets a provenance tag
(imported / contract-pin / derivation comment); import where an export
exists (NJ_SCALE, face constants via cityModel exports).

### F7 — probe-resize's pass is the absence of a foreign string
l.13/242: fails only if a console error contains 'Destroyed texture'. If
Dawn rewords, or Chromium reroutes the message, the probe passes forever.
Mitigation on record: it was watched failing pre-fix (STATUS 2026-07-18,
practice 5). Cheap hardening: a `--expect-fail` self-test mode, or assert
at least that the console listener saw N>0 total messages per run.

### Family IV sweep (aggregation destroys the reading) — CLEAN
Checked every accumulation loop: probe-walkfling maxJump (max-reduce, A2),
probe-ascent maxStep/minDrop (max/min), probe-crowd worstDrift/worstTotal
(max), probe-walkfling-live maxUpJump (max), probe-ambience (harness sums
all samples), probe-cloudlag (counts). No last-iteration-overwrite bug
found. probe-crowd's B1/E2 `detail` strings are overwritten per iteration
but the `ok` flag latches false — verdict unaffected.
